# 订阅地址就是最终 GET 端点，不设「接口服务地址」

app 对用户填入的订阅地址做原样 GET，响应即标准格式清单：不做基址拼接、不加 `?url=` 参数、不改写路径。因此设置界面**没有**独立的「接口服务地址」项，订阅地址自己就说明了它从哪儿来。

**状态**：取代早期"全局服务地址、空=直连，非空则所有订阅一律走代理"的路由方案（那版曾记录在 ADR-0001/0003 的措辞里，两文已就地改写为本口径）。

**理由**：参数化代理要求 app 理解"基址 + 目标"的两段语义，并要求服务端在运行时拉取请求带来的任意 URL（SSRF 面、鉴权、限流、隐私全部跟随而来）。固定端点把这些一次性消掉：服务端退化为部署者自配的只读清单，可挂 CDN、可公开发布、可被任何 app 版本消费。

**后果**：第三方非标准链接的兼容成本从"填一个服务地址"变成"找到一个已转好的地址"；`serverless/` 里的订阅服务样例承担这一步。多一层配置项被彻底去掉，符合"配置只留一个旋钮"。
