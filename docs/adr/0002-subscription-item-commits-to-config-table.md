# 订阅条目落入现有 Config 表，不另建生效机制

用户在订阅列表里选中一条条目时，app 把它的名称 + URL 写入现有的 `Config` 表（与手动填写资源地址走完全相同的落库与加载流程），选中之后它就是一条普通的「生效中的资源地址」。订阅不维护独立的生效状态。

**理由**：现有 `Config`（按 `type` 0/1/2 区分点播/直播/壁纸，SharedPreferences 键 `config_<type>` 记当前生效）已经是唯一的事实来源；引入"订阅态生效"会造成两套并行机制，历史列表、远程管理、备份等既有能力都要各自适配。

**备选方案（已否决）**：不落库、每次启动从订阅源实时加载——断网或代理服务不可用时直接没源。落库快照 + 额外记录来源订阅并做失效比对——多一个字段与同步规则，收益当前不明显。
